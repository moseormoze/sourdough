# Feature: פיילוט חזותי לרדזיין

## Problem
שפת הרדזיין המוצעת משנה בבת אחת צבע, משטחים, היררכיית תוכן, התקדמות וטיימר.
אם ניישם אותה ישירות במסכי production, יהיה קשה להבחין אם בעיה נובעת מהכיוון
החזותי או מהלוגיקה, והחזרה לאחור תיגע במספר רב של רכיבים ו-workstreams פעילים.
נדרש artifact מבודד שמאפשר לראות את הכיוון על מסכים אמיתיים בעברית, להשוות אותו
למצב הנוכחי ולהכריע את השאלות הפתוחות לפני שמאשרים רדזיין רחב.

## User Story
כבעל המוצר, אני רוצה לצפות בכיוון הרדזיין על מספר קטן של מסכים מייצגים ולבדוק
את האינטראקציות המרכזיות, כדי להחליט בביטחון מה מאמצים לפני שמשנים את האפליקציה
הפעילה.

## Scope — What's In
- canvas עצמאי בתוך `specs/design/visual-reference/`, המבוסס על תשתית ה-HTML,
  React וה-artboards הקיימת.
- ארבעה מצבי פיילוט ברוחב 375px: בית עם בייק פעיל, תסיסה ראשונית (״באלק״), שלב
  עם טיימר ומפת המסע הפתוחה.
- השוואה למצב הנוכחי באותם אזורים שבהם היא מסייעת לקבל החלטה.
- עברית מלאה ו-RTL, עם תוכן דוגמה מציאותי מהאפליקציה.
- בדיקת השפה החזותית המוצעת: גרדיאנט כתום–כחול, זכוכית במשטחים משניים, מוקד שחור
  יחיד במסך ומשטחים אטומים לטקסט ארוך.
- בדיקת היררכיית מסך השלב: הקשר קצר, פעולה מיידית, סימני מעבר ותוכן העמקה.
- אינטראקציות הערכה בלבד: פתיחת וסגירת מפת המסע, preview של שלב ומעבר בין מצבי
  תצוגה של הטיימר.
- מסלול תחזית מוצע בכרטיס הבייק הפעיל, כולל מצב fallback ללא שעת סיום.

## Out of Scope
- שינוי של routes, רכיבי production, hooks, storage, analytics או נתוני משתמש.
- החלפת tokens או עדכון `context/design-system.md` לפני אישור הפיילוט.
- מימוש לוגיקת הטיימר, persistence או עריכת זמן; אלה בבעלות Feature 27.
- חישוב production של תחזית סיום הבייק או שינוי מנוע התזמון.
- רדזיין של כל מסכי האפליקציה, תמיכה בדסקטופ או יצירת נכסי צילום חדשים.
- חיבור הפיילוט לנתוני משתמש אמיתיים או פריסתו כחלק מהאפליקציה הפעילה.

## Acceptance Criteria
- [ ] קובץ הכניסה לפיילוט נפתח בדפדפן ומציג canvas ללא שינוי ב-route של האפליקציה.
- [ ] ה-canvas כולל ארבעה artboards מזוהים: בית פעיל, באלק, שלב עם טיימר ומפת מסע.
- [ ] כל artboard מוצג ברוחב 375px, עם `dir="rtl"` וטקסט עברי אמיתי.
- [ ] במסך הבאלק מופיעים לפי הסדר stepper, משפט הקשר קצר, ״מה עושים עכשיו״,
  ״מתי ממשיכים״ וכניסות העמקה.
- [ ] ה-stepper פותח את מפת המסע; לחיצה על שלב אחר מציגה preview ואינה מדמה מעבר
  שלב או שינוי בנתוני הבייק.
- [ ] פיילוט הטיימר מאפשר להציג לפחות מצבי לפני התחלה, פעיל, מושהה והסתיים בלי
  לממש persistence או לשנות את Feature 27.
- [ ] כרטיס הבייק הפעיל מציג תחזית כטווח עם ניסוח מסויג ומדגים גם fallback ללא
  תחזית זמן.
- [ ] בכל artboard יש לכל היותר מוקד שחור אחד; טקסט ארוך מופיע על משטח אטום.
- [ ] יעדי המגע הפעילים הם 44×44px לפחות, press feedback הוא 120ms, ותנועות של
  250ms מכבדות `prefers-reduced-motion`.
- [ ] השינוי אינו נוגע בקבצים תחת `app/`, `components/` או `lib/`.
- [ ] לאחר סקירת ה-canvas מתועדות החלטות adopt / revise / reject לכל אחד מארבעת
  תחומי הבדיקה: שפה חזותית, היררכיית שלב, מפת מסע וטיימר/תחזית.

## Dependencies
- Depends on: `specs/discovery/22-redesign-pilot.md`, תבנית התוכן של Feature 26
  ומפרט ההתנהגות של Feature 27 כמקורות התייחסות בלבד.
- Blocks: החלטה אם לפתוח פיצ׳ר production לרדזיין ועדכון ה-design system הקנוני.

## Open Questions

לא כחוסמי scope.
