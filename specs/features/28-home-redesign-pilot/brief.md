# Feature: פיילוט רידזיין למסך הבית

## Problem

מסך הבית משמש גם כנקודת פתיחה לבייק חדש וגם כשער חזרה לבייק פעיל. כיום משתמש
שחוזר באמצע אפייה רואה רק את שם המתכון ומספר השלב, ולכן חייב להיכנס למסך השלב
כדי להיזכר מהו השלב ומה מצב הטיימר או הקיפולים שנשמר. בזמן טעינת הבייק הפעיל גם
עלול להופיע לרגע הבית הריק, עם פעולה ראשית שגויה ושינוי פריסה. במקביל, השפה
החזותית החדשה שהוכחה באוטוליזה עדיין אינה קיימת במסך גלובלי, ולכן אי אפשר לדעת
אם היא מתאימה להרחבה לשאר האפליקציה.

## User Story

כאופה ביתי שפותח את כיכר לפני בייק או חוזר אליה באמצע אפייה, אני רוצה לזהות מיד
אם יש בייק פעיל, באיזה שלב הוא ומה מצב הטיימר או הקיפולים שנשמר, כדי להתחיל או
להמשיך בלי לשחזר בעצמי את ההקשר.

## Scope — What's In

- שלושה מצבי Home: טעינה, fresh ללא בייק פעיל ו־active/resume.
- במצב fresh: התחלת אפייה כמוקד הראשי; מתכונים וסטארטר כניווט משני קומפקטי.
- במצב active: הבייק הפעיל כמוקד הראשי, עם שם המתכון, שם ומספר השלב ואות מצב
  דטרמיניסטי מתוך המידע הקיים — טיימר קודם, או התקדמות קיפולים בשלב המתאים.
- המשך לשלב הפעיל בלחיצה אחת. התחלת בייק חדש, מתכונים וסטארטר נשארים זמינים
  כפעולות משניות; חוזה החלפת הבייק הקיים נשמר בהמשך הזרימה.
- ספירת המתכונים הקיימת כאשר היא גדולה מאפס.
- `InstallBanner` במצב fresh לפי התנאים הקיימים, כולל התאמה מקומית של
  `InstallGuideSheet` לשפת הפיילוט.
- `StopBakeDialog` מתוך כרטיס הבייק הפעיל, עם התאמה מקומית לשפת הפיילוט.
- התאמת מיקום הבית ל־Feedback FAB ול־safe area, בלי לעצב מחדש את ה־FAB או ה־sheet.
- שפת הפיילוט: גרדיאנט בקנבס הבית, משטחי glass שקופים, inset חלש למידע מקונן
  ומוקד charcoal יחיד בכל מצב.
- חוזי press, מקלדת, reduced motion, RTL, הגדלת טקסט ויעדי מגע של 44px לפחות.

## Out of Scope

- שינוי `WelcomeGate`, ‏Feedback sheet, מסכי היעד או ניווט גלובלי.
- סטטוס סטארטר חי בבית, תלות Supabase חדשה, היסטוריית בייקים או תוכן הדרכתי.
- שינוי מודל `ActiveBake`, התנהגות הטיימר, storage, sync, offline או שחזור מידע
  פגום.
- חיווי “מוכן”, “באיחור” או המלצה לפעולה שאינם נגזרים מהמידע הקיים.
- שינוי תנאי ההתקנה, routes, אירועי analytics או זרימות האישור הקיימות.
- החלת הרידזיין על מתכונים, סטארטר, planner או שלבי אפייה נוספים.
- שינוי ברירות המחדל של `Button`, ‏`Dialog`, ‏`BottomSheet`, ‏`FeedbackFab`,
  `html` או `body`; וריאנט מקומי ל־Home מותר רק אם שאר האפליקציה אינה משתנה.
- יצירת primitives גלובליים כמו `GlassCard` או `AmbientPage` לפני שמסך נוסף
  מוכיח API משותף.
- כתיבה או שינוי של קופי ללא אישור המשתמש.

## Acceptance Criteria

- [ ] כל עוד מצב `activeBake` לא הוכרע, Home אינו מציג את הפעולה הראשית של fresh
      או הצעת התקנה; לאחר הטעינה מוצג בדיוק מצב fresh או active ללא הבהוב ביניהם.
- [ ] ב־fresh, הפעולה הראשית מובילה ל־`/bake/new`; מתכונים וסטארטר מובילים
      ל־`/recipes` ול־`/starter`; מונה מתכונים מופיע רק כשהמספר גדול מאפס.
- [ ] ב־active, הבייק הפעיל הוא המוקד החזותי היחיד ומציג את שם המתכון, שם השלב
      מתוך `STAGES` ואת `currentStage/12`, בלי להמציא מוכנות או דחיפות.
- [ ] אות המצב משתמש בסדר קבוע: טיימר שהתחיל, הושהה או הסתיים מוצג ראשון;
      אחרת, בשלב הקיפולים מוצגת ההתקדמות הנוכחית מתוך הסך; אחרת לא מוצג סטטוס
      מומצא.
- [ ] עבור אותו `ActiveBake` ואותו זמן ייחוס, Home ומסך השלב מציגים אותו מצב
      טיימר ואותו זמן נותר. reload מחשב נכון זמן שעבר וטיימר מושהה נשאר קפוא.
- [ ] פעולת המשך מובילה ל־`/bake/stage/{currentStage}`. התחלת בייק חדש אינה
      מוחקת את הבייק הפעיל ועוברת דרך חוזה ההחלפה הקיים.
- [ ] עצירת בייק נשארת מאחורי אישור: ביטול שומר את הבייק; אישור רושם
      `bake_abandoned` עם נתוני הבייק הנוכחי לפני מחיקת המידע השמור.
- [ ] `InstallBanner` מוצג רק ב־fresh ולפי תנאי iOS, Android, Facebook,
      dismissed ו־installed הקיימים; פעולות, exit ו־analytics אינם משתנים.
- [ ] `InstallGuideSheet` ו־`StopBakeDialog` מקבלים וריאנט Home מקומי; ברירת
      המחדל שלהם וכל הופעה מחוץ ל־Home נשארות זהות.
- [ ] בכל מצב יש משטח charcoal אחד בלבד, ללא שחור טהור. הגרדיאנט שייך לקנבס
      Home, והמשטחים הרגילים שקופים, קריאים ובעלי fallback ללא `backdrop-filter`.
- [ ] ב־375×812, ב־320px וב־200% text אין overflow אופקי, חיתוך פעולה, חפיפת
      FAB/safe area או אזור בלתי נגיש. שם מתכון ארוך נשאר קריא ואינו מסתיר פעולה.
- [ ] כל יעד מגע הוא 44×44px לפחות. ניווט ו־resume משתמשים בחוזה
      `usePressActivation`: משוב press, ביטול בתנועה מעל 5px, cleanup וללא הפעלה
      מקרית אחרי drag.
- [ ] אפשר להפעיל את כל הפעולות במקלדת עם `focus-visible`; reduced motion מסיר
      משוב תלוי־transform אך משאיר משוב נראה אחר.
- [ ] יש H1 נגיש אחד והלוגו אינו מוכרז שוב. מצב טיימר וקיפולים אינו מועבר בצבע
      בלבד; זמן אינו יוצר הכרזת live בכל שנייה.
- [ ] מספרי שלב, קיפולים וזמן מבודדים נכון בתוך RTL, עם סמנטיקת current/total
      וקריאות תקינה לקורא מסך.
- [ ] routes, localStorage, recipe count, install eligibility ו־analytics עוברים
      בדיקות רגרסיה; אין שינוי schema או storage keys.
- [ ] QA מרונדר מכסה loading; fresh עם ובלי מתכונים; כל מצבי ההתקנה; active ללא
      טיימר, עם טיימר רץ/מושהה/שהסתיים ועם קיפולים; שם ארוך; ודיאלוג עצירה פתוח.
      מקור ובדיקות בלבד אינם אישור ויזואלי.
